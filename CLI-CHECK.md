# Проверка Дня 23 через консоль

То же, что `MANUAL-CHECK.md`, но без браузера. Проверяются девять пластов:

* **новое в Дне 23** — второй этап поиска: режимы с параметрами из подбора,
  отбор по этапам (реранкер, порог отсечения, top-K до и после), query rewrite
  со слиянием, другой реранкер той же командой, подбор, ответ модели в режимах
  поиска и десять контрольных вопросов в пяти режимах;
* **наследство Дня 22** — первый RAG-запрос: вопрос → поиск чанков → фрагменты с
  паспортом в промпт → ответ со ссылками [n]; тот же вопрос без RAG; десять
  контрольных вопросов с ожиданием и источниками, оценка правилами и судьёй;
* **наследство Дня 21** — индекс документов: извлечение (PDF с текстом, сканы
  через OCR, таблицы Excel), разбиение двумя стратегиями, эмбеддинги локальной
  bge-m3, индекс в SQLite с метаданными чанков, сравнение стратегий, свой
  MCP-сервер `docs` и агент, который сам ищет в индексе;
* **наследство Дня 20** — оркестровка: агент выбирает серверы под запрос, ведёт
  длинный флоу из нескольких вызовов к разным серверам, проверяет порядок
  вызовов и останавливается перед изменением чужой системы;
* **наследство Дня 19** — конвейеры: цепочка инструментов из файла, где
  результат одного шага становится аргументом следующего;
* **наследство Дня 18** — планировщик и работник: задание переживает процесс,
  выполняется без человека, накопленное сводится в сводку;
* **наследство Дня 17** — свой MCP-сервер вокруг API трекера: вызовы руками и
  моделью, заявка на всё, что меняет чужие данные;
* **наследство Дня 16** — подключение MCP как таковое: список серверов,
  соединение по stdio и HTTP, фильтр, понятные сбои;
* **наследство Дней 11–15** — слои памяти и разбор промпта, заготовки профиля,
  пауза, инварианты с отказом за ноль токенов, ворота переходов и диалоговый
  режим.

Мок-трекер поднимает сам скрипт прогона — на свободном порту и со своими
данными в `cli-check-memory/tracker-data.json`. Работника он тоже запускает сам,
там, где это нужно по шагу. Руками запускать ничего не нужно.

```bash
cd ~/Документы/AI-Advent-Challenge/Day-23
.venv/bin/python check_cli.py                # весь чек-лист + отчёт в CLI-CHECK-RESULTS.md
.venv/bin/python check_cli.py --без-модели   # без живых вызовов модели
.venv/bin/python check_cli.py --в отчёт.md
```

Ниже вместо `.venv/bin/python` написано просто `python`: так короче, а с
активированным окружением (`source .venv/bin/activate`) это одно и то же.
Команды подразумевают файл серверов прогона
(`cli-check-memory/mcp-configs/orchestra.json` для оркестровки,
`…/pipeline.json` для конвейеров, `…/scheduler.json` для планировщика,
`…/tracker.json` для трекера); вручную то же самое делается с
`mcp-servers.json`, если в соседнем терминале поднят `python tracker_api.py`.

Память у всего прогона одна (`cli-check-memory/`), поэтому номера заданий,
заявок, прогонов и флоу сквозные: заявку №1 заводит длинный флоу из части 3,
№2 — конвейер из части 6, №3 — планировщик из части 9, №4 — трекер из части 15.

Индекс для части 0 — копия рабочего `index/` в `cli-check-memory/index/`
(ключ `--индекс-в`). Рабочий индекс собирается заранее одной командой
`python cli.py --индексировать`: первая сборка на CPU идёт около часа (OCR
сканов и векторы bge-m3), а в копии все векторы уже в кэше, и пересборка в
чек-листе идёт секунды. Ollama с моделью `bge-m3` должна быть запущена.
